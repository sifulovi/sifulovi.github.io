## Time Complexity আসলে কী?

**সংজ্ঞা:** ইনপুটের আকার বাড়লে একটা অ্যালগরিদমের **চলার সময় কত দ্রুত বাড়ে** — সেটার পরিমাপ।

**⚠️ সবচেয়ে গুরুত্বপূর্ণ কথা:** এটা **সেকেন্ডে সময় মাপে না**! এটা মাপে **বৃদ্ধির হার**।

> **বাস্তব উদাহরণ — বইয়ে একটা শব্দ খোঁজা 📖**
>
> | বইয়ের পৃষ্ঠা | ১ পাতা করে খোঁজা (O(n)) | ইনডেক্স দেখে খোঁজা (O(log n)) |
> |---|---|---|
> | ১০০ পৃষ্ঠা | ১০০ ধাপ | ~৭ ধাপ |
> | ১,০০০ পৃষ্ঠা | ১,০০০ ধাপ | ~১০ ধাপ |
> | ১০,০০,০০০ পৃষ্ঠা | ১০,০০,০০০ ধাপ 😩 | **~২০ ধাপ** ⚡ |
>
> খেয়াল করুন — বই ১০,০০০ গুণ বড় হলো, কিন্তু ইনডেক্সে খোঁজার ধাপ বাড়ল মাত্র ৩ গুণ! **এটাই complexity-র শক্তি।**

## বৃদ্ধির হার — ছোট থেকে বড়

```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
 ↑                                                              ↑
সেরা                                                         ভয়ংকর
```

**n = ১০ লক্ষ হলে বাস্তবে কত সময় লাগবে** (সেকেন্ডে ১০ কোটি অপারেশন ধরে):

| Complexity | অপারেশন সংখ্যা | সময় | রায় |
|---|---|---|---|
| **O(1)** | ১ | তাৎক্ষণিক | 🟢 সেরা |
| **O(log n)** | ~২০ | তাৎক্ষণিক | 🟢 চমৎকার |
| **O(n)** | ১০,০০,০০০ | ০.০১ সেকেন্ড | 🟢 ভালো |
| **O(n log n)** | ২ কোটি | ০.২ সেকেন্ড | 🟡 গ্রহণযোগ্য |
| **O(n²)** | ১০¹² | **৩ ঘণ্টা** | 🔴 খারাপ |
| **O(2ⁿ)** | ২^১⁰⁰⁰⁰⁰⁰ | **মহাবিশ্বের বয়সের চেয়ে বেশি** | ⚫ অসম্ভব |

## প্রতিটা Complexity বাস্তব উদাহরণ দিয়ে

### O(1) — Constant Time (স্থির সময়)
ইনপুট যত বড়ই হোক, **সময় একই**।

> **উপমা:** বইয়ের **৫০ নম্বর পৃষ্ঠা** খোলা। বই ১০০ পাতার হোক বা ১০,০০০ পাতার — সোজা ৫০ নম্বরে যান। ✅

```go
arr[5]              // array-তে index দিয়ে অ্যাক্সেস
m["key"]            // hash map-এ খোঁজা
stack.Push(x)       // stack-এ যোগ
```

### O(log n) — Logarithmic (লগারিদমিক)
প্রতি ধাপে **কাজের অর্ধেক বাদ** পড়ে যায়।

> **উপমা:** ফোন বইয়ে নাম খোঁজা। মাঝখানে খুলুন → নামটা কি আগে না পরে? → অর্ধেক বাদ → আবার মাঝখানে... ✅

```go
BinarySearch(sortedArr, target)     // O(log n)
tree.Search(key)                     // Balanced BST
heap.Push(x)                         // O(log n)
```

**কেন এত দ্রুত:** ১০ লক্ষ এলিমেন্টে মাত্র **২০ ধাপ** (২²⁰ ≈ ১০ লক্ষ)।

### O(n) — Linear (রৈখিক)
প্রতিটা এলিমেন্ট **একবার** করে দেখা।

> **উপমা:** ক্লাসে রোল কল করা — ৪০ জন হলে ৪০ বার নাম ডাকতে হবে।

```go
for _, v := range arr { }           // পুরো তালিকা ঘোরা
LinearSearch(arr, target)
Max(arr)                             // সর্বোচ্চ খোঁজা
```

### O(n log n) — Linearithmic
**দক্ষ সাজানোর (sorting) সীমা** — তুলনাভিত্তিক sorting এর চেয়ে দ্রুত হতে পারে না।

```go
sort.Ints(arr)      // Go-এর built-in sort
MergeSort(arr)
QuickSort(arr)      // গড়ে
HeapSort(arr)
```

> **উপমা:** ১০০০টা কার্ড সাজানো — বারবার অর্ধেক করে ভাগ (log n) করে প্রতিটা ভাগে সব কার্ড মেলানো (n)।

### O(n²) — Quadratic (বর্গীয়)
**নেস্টেড লুপ** — সাধারণত এড়ানো উচিত।

> **উপমা:** ক্লাসের **প্রত্যেকে প্রত্যেকের সাথে** হাত মেলাচ্ছে। ১০ জনে ৪৫ বার, ১০০ জনে ৪,৯৫০ বার! 😩

```go
for i := range arr {
    for j := range arr {     // 👈 দুইটা নেস্টেড লুপ
        // ...
    }
}
BubbleSort(arr)
SelectionSort(arr)
```

**⚠️ n > ১০,০০০ হলে O(n²) কার্যত অচল।**

### O(2ⁿ) — Exponential (সূচকীয়)
প্রতিটা নতুন ইনপুটে কাজ **দ্বিগুণ** হয়ে যায়।

```go
// ❌ ভয়ংকর — Fibonacci রিকার্শন (memoization ছাড়া)
func Fib(n int) int {
    if n <= 1 { return n }
    return Fib(n-1) + Fib(n-2)      // n=50 হলে কয়েক মিনিট!
}

// ✅ Dynamic Programming দিয়ে O(n)
func Fib(n int) int {
    a, b := 0, 1
    for i := 0; i < n; i++ { a, b = b, a+b }
    return a
}
```

> **বিখ্যাত উপমা — গমের দানার গল্প:** দাবার বোর্ডের প্রথম ঘরে ১টা দানা, পরের ঘরে দ্বিগুণ... ৬৪তম ঘরে পৌঁছাতে পুরো পৃথিবীর গম লেগে যাবে! 🌾

### O(n!) — Factorial
**সব সম্ভাব্য বিন্যাস** চেষ্টা করা।

```go
// Traveling Salesman (brute force)
// n=১০ → ৩৬ লক্ষ, n=২০ → ২.৪×১০¹⁸ 💀
```

## ডেটা স্ট্রাকচার — অপারেশনের জটিলতা

| ডেটা স্ট্রাকচার | Access | Search | Insert | Delete |
|---|---|---|---|---|
| **Array** | **O(1)** ✅ | O(n) | O(n) | O(n) |
| **Dynamic Array** (slice) | **O(1)** ✅ | O(n) | O(1)* শেষে | O(n) |
| **Linked List** | O(n) | O(n) | **O(1)** ✅ | **O(1)** ✅ |
| **Stack** | O(n) | O(n) | **O(1)** ✅ | **O(1)** ✅ |
| **Queue** | O(n) | O(n) | **O(1)** ✅ | **O(1)** ✅ |
| **Hash Table** | — | **O(1)** ✅ | **O(1)** ✅ | **O(1)** ✅ |
| **Binary Search Tree** | O(log n) | O(log n) | O(log n) | O(log n) |
| **BST (worst case)** | O(n) ⚠️ | O(n) | O(n) | O(n) |
| **AVL / Red-Black Tree** | O(log n) | O(log n) | O(log n) | O(log n) |
| **Heap** | O(1) (min/max) | O(n) | O(log n) | O(log n) |
| **B+ Tree** | O(log n) | O(log n) | O(log n) | O(log n) |

> `*` **Amortized O(1)** — মাঝে মাঝে array বড় করতে হয় (O(n)), কিন্তু **গড়ে** O(1)।
>
> **⚠️ Hash Table-এর worst case O(n)** — যদি সব key একই bucket-এ পড়ে (খারাপ hash function বা ইচ্ছাকৃত আক্রমণ)।

## Sorting অ্যালগরিদম

| অ্যালগরিদম | Best | Average | Worst | Space | Stable? |
|---|---|---|---|---|---|
| **Bubble Sort** | O(n) | O(n²) | O(n²) | O(1) | ✅ |
| **Selection Sort** | O(n²) | O(n²) | O(n²) | O(1) | ❌ |
| **Insertion Sort** | O(n) | O(n²) | O(n²) | O(1) | ✅ |
| **Merge Sort** | O(n log n) | O(n log n) | **O(n log n)** ✅ | O(n) | ✅ |
| **Quick Sort** | O(n log n) | O(n log n) | O(n²) ⚠️ | O(log n) | ❌ |
| **Heap Sort** | O(n log n) | O(n log n) | **O(n log n)** ✅ | O(1) ✅ | ❌ |
| **Counting Sort** | O(n+k) | O(n+k) | O(n+k) | O(k) | ✅ |
| **Radix Sort** | O(nk) | O(nk) | O(nk) | O(n+k) | ✅ |

**"Stable" মানে কী:** সমান মানের এলিমেন্টগুলোর **আপেক্ষিক ক্রম বজায় থাকে**।
> **কেন গুরুত্বপূর্ণ:** কর্মীদের আগে **নাম** দিয়ে সাজালেন, তারপর **বিভাগ** দিয়ে। Stable sort হলে একই বিভাগের ভেতরে নামের ক্রম ঠিক থাকবে ✅

**⚠️ Quick Sort-এর worst case কখন:** ইতিমধ্যে সাজানো তালিকায় সবসময় প্রথম এলিমেন্টকে pivot বাছলে → O(n²)। **সমাধান:** এলোমেলো pivot বা median-of-three।

**কখন কোনটা:**
```
সাধারণ ক্ষেত্রে       → Quick Sort (বাস্তবে সবচেয়ে দ্রুত)
worst case গ্যারান্টি → Merge Sort বা Heap Sort
প্রায় সাজানো ডেটা      → Insertion Sort (O(n)!)
মেমরি খুব কম          → Heap Sort (O(1) space)
ছোট রেঞ্জের সংখ্যা     → Counting Sort (O(n)!)
```

## Graph অ্যালগরিদম

*(V = vertex সংখ্যা, E = edge সংখ্যা)*

| অ্যালগরিদম | Time | Space | কী করে |
|---|---|---|---|
| **BFS** | O(V+E) | O(V) | সবচেয়ে কম **ধাপের** পথ |
| **DFS** | O(V+E) | O(V) | গভীরে খোঁজা, চক্র শনাক্ত |
| **Dijkstra** | O((V+E) log V) | O(V) | সবচেয়ে কম **ওজনের** পথ |
| **Bellman-Ford** | O(V×E) | O(V) | ঋণাত্মক ওজনও চলে |
| **Floyd-Warshall** | O(V³) | O(V²) | সব জোড়ার মধ্যে কম পথ |
| **Kruskal (MST)** | O(E log E) | O(V) | সর্বনিম্ন বিস্তৃত গাছ |
| **Prim (MST)** | O(E log V) | O(V) | সর্বনিম্ন বিস্তৃত গাছ |
| **Topological Sort** | O(V+E) | O(V) | নির্ভরতার ক্রম |

**BFS বনাম DFS — কখন কোনটা:**
```
BFS → সবচেয়ে কাছের/সংক্ষিপ্ততম কিছু খুঁজতে (unweighted graph)
      উদাহরণ: "আমার বন্ধুর বন্ধুদের মধ্যে কে আছে?" (২ ধাপ দূরত্ব)

DFS → পুরো পথ ঘুরে দেখতে, চক্র শনাক্ত, topological sort
      উদাহরণ: গোলকধাঁধা থেকে বেরোনোর পথ খোঁজা
```

## Space Complexity (জায়গার জটিলতা)

শুধু সময় নয় — **কত মেমরি লাগছে** সেটাও গুরুত্বপূর্ণ।

```go
// O(1) space — অতিরিক্ত জায়গা লাগছে না
func Sum(arr []int) int {
    total := 0                    // একটাই ভেরিয়েবল
    for _, v := range arr { total += v }
    return total
}

// O(n) space — ইনপুটের সমান জায়গা
func Double(arr []int) []int {
    result := make([]int, len(arr))    // 👈 নতুন array
    for i, v := range arr { result[i] = v * 2 }
    return result
}
```

**⚠️ রিকার্শনের লুকানো খরচ:** প্রতিটা রিকার্সিভ কল **stack-এ জায়গা** নেয়!
```go
func Factorial(n int) int {
    if n <= 1 { return 1 }
    return n * Factorial(n-1)     // O(n) space! (stack frame)
}
```
n খুব বড় হলে → **stack overflow** 💥

## Big O, Big Ω, Big Θ

| চিহ্ন | মানে | উপমা |
|---|---|---|
| **O** (Big O) | **উপরের সীমা** — সবচেয়ে খারাপ ক্ষেত্রে | "সর্বোচ্চ ২ ঘণ্টা লাগবে" |
| **Ω** (Omega) | **নিচের সীমা** — সবচেয়ে ভালো ক্ষেত্রে | "কমপক্ষে ৩০ মিনিট লাগবেই" |
| **Θ** (Theta) | **কঠিন সীমা** — দুটোই একই | "ঠিক ১ ঘণ্টা লাগবে" |

> **বাস্তবে সবাই "Big O" বলে, কিন্তু আসলে Θ বোঝায়।** ইন্টারভিউয়ে এটা জানা থাকলে ভালো, তবে খুঁটিনাটিতে না গিয়ে সবচেয়ে খারাপ ক্ষেত্রটা বলাই যথেষ্ট।

## Complexity হিসাব করার নিয়ম

**নিয়ম ১ — ধ্রুবক বাদ দিন:**
```
O(2n) → O(n)
O(500) → O(1)
O(n/2) → O(n)
```
> কারণ n খুব বড় হলে ধ্রুবকের প্রভাব নগণ্য।

**নিয়ম ২ — শুধু সবচেয়ে বড় পদটা রাখুন:**
```
O(n² + n + 100) → O(n²)
O(n log n + n) → O(n log n)
```

**নিয়ম ৩ — নেস্টেড লুপ = গুণ:**
```go
for i := 0; i < n; i++ {         // n বার
    for j := 0; j < m; j++ {     // × m বার
        // ...                    // = O(n×m)
    }
}
```

**নিয়ম ৪ — পরপর লুপ = যোগ:**
```go
for i := 0; i < n; i++ { }       // O(n)
for j := 0; j < m; j++ { }       // O(m)
// মোট = O(n + m)
```

**⚠️ একটা ফাঁদ:**
```go
for i := 0; i < n; i++ {
    if arr.Contains(x) { }        // 👈 এটা নিজেই O(n)!
}
// মোট = O(n²), O(n) নয়!
```
লুপের ভেতরে ডাকা ফাংশনগুলোর complexity-ও হিসাবে ধরুন।

## 📌 দ্রুত রিভিশন চিট-শিট

### ইনপুটের আকার দেখে অ্যালগরিদম বাছাই

*(প্রতিযোগিতামূলক প্রোগ্রামিংয়ে ~১ সেকেন্ড সময়সীমা ধরে)*

| n-এর আকার | সর্বোচ্চ যে complexity চলবে |
|---|---|
| n ≤ ১০ | O(n!) |
| n ≤ ২০ | O(2ⁿ) |
| n ≤ ৫০০ | O(n³) |
| n ≤ ৫,০০০ | O(n²) |
| n ≤ ১০ লক্ষ | **O(n log n)** |
| n ≤ ১ কোটি | **O(n)** |
| n যত বড়ই হোক | O(log n), O(1) |

> **💡 ইন্টারভিউ টিপ:** সমস্যায় "n ≤ ১০⁵" দেখলেই বুঝবেন **O(n²) চলবে না** — O(n log n) বা তার চেয়ে ভালো সমাধান খুঁজতে হবে।

### অপ্টিমাইজেশনের সাধারণ কৌশল

| ধীর | দ্রুত | কৌশল |
|---|---|---|
| O(n) খোঁজা | O(1) | **Hash Map** ব্যবহার করুন |
| O(n²) নেস্টেড লুপ | O(n) | Hash Map বা **দুই পয়েন্টার** |
| O(n) সাজানো তালিকায় খোঁজা | O(log n) | **Binary Search** |
| O(2ⁿ) রিকার্শন | O(n) | **Memoization / DP** |
| বারবার একই হিসাব | O(1) | **Precompute / Prefix Sum** |

**একটা বাস্তব উদাহরণ — Two Sum:**
```go
// ❌ O(n²)
for i := range arr {
    for j := i+1; j < len(arr); j++ {
        if arr[i]+arr[j] == target { return i, j }
    }
}

// ✅ O(n) — Hash Map দিয়ে
seen := map[int]int{}
for i, v := range arr {
    if j, ok := seen[target-v]; ok { return j, i }
    seen[v] = i
}
```
**মূল ধারণা:** একটু বেশি **মেমরি** খরচ করে অনেক **সময়** বাঁচানো। এটাকে বলে **space-time tradeoff**।

### ইন্টারভিউয়ে যা মনে রাখবেন

1. ✅ সমাধান লেখার পর **নিজে থেকেই** complexity বলুন — জিজ্ঞেস করার আগে
2. ✅ **Time এবং Space** দুটোই বলুন
3. ✅ "এটা O(n²), তবে Hash Map দিয়ে O(n) করা যায়" — **উন্নতির পথ** দেখান
4. ✅ Worst case বলুন, তবে average case আলাদা হলে সেটাও উল্লেখ করুন
5. ✅ রিকার্শনে **stack space**-এর কথা ভুলবেন না
